# RELEASING

Всё, что нужно, чтобы выложить MacPulse людям. Читается сверху вниз один раз,
дальше — только раздел «Каждый релиз».

---

## 0. Состояние на сейчас

Репозиторий локальный: 50 коммитов реальной истории, **remote нет**,
релизов нет. Ни одна команда ниже ещё не выполнялась. `release.sh` по
умолчанию работает в режиме сухого прогона и специально не умеет ничего
опубликовать без явного `--publish`.

**Порядок имеет значение.** Команда установки в README тянет файл по адресу
`raw.githubusercontent.com/<owner>/<repo>/main/install.sh`, а сам установщик
берёт сборку из `releases/latest`. Значит:

1. сначала пуш ветки `main` — иначе `curl` вернёт 404 на сам скрипт;
2. только потом релиз — иначе скрипт запустится, но скачать ему будет нечего.

`release.sh --publish` делает оба шага в этом порядке.

## 1. Один раз: создать репозиторий на GitHub и запушить историю

**Перед первой командой** — проверьте, что в истории нет ничего личного.
Вся история уходит целиком, и переписать её после публикации уже нельзя.
Отдельно посмотрите `docs/expanded.png`: это настоящая отрисовка островка с
настоящими данными этой машины — именами приложений и обрезанными кусками
буфера обмена. Ничего секретного там быть не должно, но посмотреть стоит
глазами, потому что картинка уедет в публичный README:

```bash
cd /Users/noname/Developer/MacPulse

# Что вообще лежит в репозитории (ожидаются только исходники и скрипты)
git ls-files | sed 's|/.*||' | sort -u

# Нет ли в истории ключей, токенов и .p12
git log --all --diff-filter=A --name-only --pretty=format: \
  | sort -u | grep -iE '\.(p12|pem|cer|key)$|secret|token' || echo "чисто"
```

Дальше одна команда создаёт публичный репозиторий, прописывает `origin` и
пушит текущую ветку:

```bash
gh repo create borissharikoff-droid/MacPulse \
  --public \
  --source=. \
  --remote=origin \
  --push \
  --description "Монитор в вырезе MacBook, который измеряет churn компрессора памяти — настоящий сигнал лагов на 8 ГБ Apple Silicon"
```

То же самое руками, если хочется контроля по шагам:

```bash
gh repo create borissharikoff-droid/MacPulse --public --description "..."
git remote add origin https://github.com/borissharikoff-droid/MacPulse.git
git push -u origin main
```

Проверка, что получилось:

```bash
git remote -v
gh repo view borissharikoff-droid/MacPulse --web
```

> Приватный репозиторий тоже работает — но тогда самообновление сломается:
> `api.github.com/repos/.../releases/latest` без токена вернёт 404, и
> приложение честно скажет «обновлений нет». Для публичной раздачи нужен
> `--public`.

## 2. Каждый релиз

```bash
./release.sh 1.0.0                 # сухой прогон: печатает план, не пишет ничего
./release.sh 1.0.0 --local         # собрать артефакты здесь и посмотреть на них
./release.sh 1.0.0 --publish       # коммит, тег, push, GitHub Release
```

Что делает `--publish`, по шагам:

1. `CFBundleShortVersionString` := версия, `CFBundleVersion` := +1.
2. `./build.sh --universal --no-install` — пин SDK, цель `macos13.0`, оба
   среза (arm64 + x86_64), все контрактные проверки по каждому срезу.
3. Копия для раздачи в `Build/dist-stage/MacPulse.app`, туда же свежий
   `Info.plist`, и **ad-hoc подпись** поверх.
4. `Build/MacPulse.zip` — `ditto -c -k --sequesterRsrc --keepParent`.
5. `Build/MacPulse-<версия>.dmg` — через `./make-dmg.sh`.
6. `git add Info.plist CHANGELOG.md` + коммит (и только эти два файла),
   тег `v<версия>`, push ветки и тега.
7. `gh release create v<версия> Build/MacPulse.zip Build/MacPulse-<версия>.dmg`,
   заметки берутся из секции `## <версия>` в `CHANGELOG.md`.

Так что порядок на практике: сначала дописать секцию в `CHANGELOG.md`,
потом `--publish`.

### Что прогнать перед `--publish`

Это те проверки, которые не может сделать CI: им нужно настоящее железо —
SMC, IOReport, HAL, — а на виртуалке раннера их может не быть, и зелёная
галочка там ничего не значила бы.

```bash
APP=Build/dist-stage/MacPulse.app/Contents/MacOS/MacPulse

# Обе архитектуры внутри одного файла
lipo -archs "$APP"                      # ждём: x86_64 arm64

# Секции и роутер: живые вкладки + выбранная вкладка не отскакивает
"$APP" --rail-probe 14                  # код возврата 0 — ни одна не отскочила

# То же самое Intel-срезом, через Rosetta. Единственный способ узнать,
# что вторая половина бинарника вообще работает, не имея Intel-мака.
arch -x86_64 "$APP" --rail-probe 14
arch -x86_64 "$APP" --printer-fuzz

# Автозапуск: включить, прочитать, что ответила macOS, вернуть как было
"$APP" --login-probe roundtrip          # код возврата 0 — переключатель двигается

# Отрисовка мимо экрана: одна точка в свёрнутом виде, ничего не обрезано
"$APP" --render-probe /tmp/mp-shots
```

### Как проверить установщик, ничего не публикуя

`install.sh` умеет брать архив откуда угодно — ровно ради этого:

```bash
MACPULSE_ZIP_URL="file://$PWD/Build/MacPulse.zip" ./install.sh
```

Это тот же самый файл и тот же самый путь кода, что и у человека с
`curl | bash`, — отличается только адрес архива. Проверять другой путь кода
значит не проверять ничего.

## 3. Чего самообновление требует от релиза

`Sources/Updater.swift` читает `releases/latest` и ищет там ровно это:

| Что | Значение | Где задаётся |
|---|---|---|
| Тег | `v<MAJOR.MINOR.PATCH>` | `release.sh` |
| Имя ассета | `MacPulse.zip` | `Updater.assetName` |
| Бандл внутри архива | `MacPulse.app` | `Updater.bundleName` |

Третья строка — та самая, за которую в соседнем проекте заплатили шестью
сломанными релизами: `ditto --keepParent` кладёт в архив имя папки **как
оно есть**, поэтому копия для раздачи собирается в отдельном каталоге уже
под правильным именем. Не переименовывайте `Build/dist-stage/MacPulse.app`.

DMG самообновление не трогает — он только для людей, которые ставят
приложение первый раз.

## 4. Если релиз оказался плохим

```bash
gh release delete v1.0.0 --yes          # убрать релиз (тег остаётся)
git push --delete origin v1.0.0         # убрать тег на сервере
git tag -d v1.0.0                       # убрать тег локально
```

Тем, кто уже успел скачать, это ничего не откатит. Быстрее и честнее
выпустить `1.0.1`: `releases/latest` у всех обновится сам в течение шести
часов.

## 5. Про идентификатор бандла — прочитать до первого релиза

`CFBundleIdentifier` сменился с `com.local.macpulse` на
`io.github.borissharikoff-droid.MacPulse`. Менять его **после** того, как
приложение у кого-то установлено, дорого: macOS по этому идентификатору
помнит и запуск при входе (`SMAppService`), и все выданные разрешения, и
настройки в `~/Library/Preferences`. Если хочется другой идентификатор —
сейчас последний момент, когда это бесплатно.

## 6. Подпись: почему ad-hoc

Платного Apple Developer ID ($99/год) нет, поэтому есть ровно два варианта.

- **Локальный самоподписанный сертификат** (`build.sh` подписывает им сборки
  для этой машины) — на чужом Маке он не привязан ни к чему доверенному, и
  macOS может объявить приложение «повреждённым». Это тупик: кнопки
  «всё равно открыть» там нет.
- **Ad-hoc подпись** (`codesign --sign -`) — даёт обычное «неизвестный
  разработчик», которое проходится правым кликом → «Открыть».

Поэтому `release.sh` пересобирает подпись в ad-hoc **для того, что уходит
людям**, а `dmg-assets/Если не открывается.txt` ведёт человека за руку.
Если когда-нибудь появится Developer ID — меняется ровно одна строка
`codesign` в `release.sh`, плюс `xcrun notarytool submit` и `xcrun stapler
staple` после неё.
